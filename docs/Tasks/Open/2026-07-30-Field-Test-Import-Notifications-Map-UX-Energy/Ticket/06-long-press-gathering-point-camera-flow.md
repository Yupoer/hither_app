# 06 — 修正長按新增集合點的相機流程

**What to build:** 使用者長按地圖時立即放大該區域以確認 pin；按下加入且保存成功後，地圖改為框住自己位置與新集合點，失敗時則保留確認卡與目前相機。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 合法長按座標只觸發一次 neighborhood zoom，縮放尺度與搜尋選點一致。
- [ ] 長按後仍顯示可編輯名稱的既有確認卡，成員與隊長維持原有權限／請求語意。
- [ ] 加入成功且有可用自己位置時，只觸發一次「自己位置 + 新集合點」的 fit。
- [ ] 加入成功但沒有可用自己位置時，退回新集合點的單點相機，不使用無效座標。
- [ ] 加入失敗、timeout 或 stale result 時不執行成功後 fit，並保留可重試的確認狀態。
- [ ] 取消新增不寫入集合點，也不觸發成功後 fit。
- [ ] 搜尋選點既有可接受相機流程不因長按修正而改變。
- [ ] 測試驗證長按、加入成功、加入失敗、缺少自己位置及重複點擊時的 imperative camera 呼叫次數與參數。
- [ ] iOS MapKit 與 Android Google Maps 各保留一次原生相機視覺驗證；無法執行時標記未驗證。
