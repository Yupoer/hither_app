# 03 — 強化 Rewarded Ads 原生邊界與生命週期復原

**What to build:** 讓商店從按下觀看廣告到等待 SSV 的完整執行期流程，在缺少模組、同意、載入、顯示、關閉與驗證失敗時都能回到可理解且可重試的狀態，不閃退、不卡死，也不錯誤發放 Token。

**Blocked by:** 01 — 蒐集 iOS Rewarded Ads 閃退與版本證據.

**Status:** ready-for-agent

- [ ] 原生廣告模組缺少、版本不相容或安裝檔過舊時，商店顯示安全的不可用／需更新狀態，程序不終止。
- [ ] UMP 尚未完成、不可請求廣告或同意流程失敗時，不建立無效廣告工作階段，並提供可重試結果。
- [ ] 廣告無填充、載入錯誤、顯示錯誤或逾時時，清理該次監聽與工作階段，CTA 回到可重試狀態。
- [ ] 使用者提前關閉廣告時不建立 Token 入帳期待，也不顯示已獲得獎勵。
- [ ] 收到手機端 rewarded callback 後只進入伺服器驗證狀態，不直接修改 wallet balance。
- [ ] 廣告關閉、錯誤與 rewarded callback 以任意合理順序到達時，狀態仍只完成一次且不殘留 listener。
- [ ] SSV 延遲時可持續顯示驗證中並重新取得 server snapshot；最終失敗或逾時後可安全重試。
- [ ] 重複點擊 CTA、重複原生事件與 stale callback 不會建立重複有效工作階段或重複發放 Token。
- [ ] 錯誤介面對使用者提供可採取的下一步；詳細技術分類只進入去識別化 diagnostics。
- [ ] 自動化測試覆蓋正常、缺少模組、同意失敗、無填充、載入／顯示失敗、提前關閉、late SSV 與重複 callback。
