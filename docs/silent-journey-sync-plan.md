# 地圖靜默同步與行程規劃

狀態：2026-09-20 grilling 已確認，待實作。本次發布只調整粒子效果；本文件不是同步重構已上線的聲明。

## 目標與現況

所有合法操作立即更新本機畫面並持久化排隊，恢復連線後自動同步。同步異常只顯示非阻斷通知，不要求使用者選擇放棄或重新套用。

目前 `coreOperationOutbox` 以帳號及群組共用 FIFO，terminal conflict 停在隊首，阻擋後續操作；`CoreSyncStatus` 因此持續要求手動處理。現有後端對落後版本及非 ACTIVE 抵達的拒絕規則也必須改造，不能只移除 UI。

## 行程與權限

- 每個主隊／小隊範圍分別維持 idle / active。開始建立新 session；結束回到 idle，卡片仍未完成。沒有額外的停止指令。
- Leader 抵達後可主動完成集合點，不等待其他人；完成同時結束 session、回到 idle，主隊卡片進入歷史。
- 刪除 ACTIVE 卡片先提示「目前進行中，是否繼續」。確認後以相依操作依序結束原 session 再刪除原卡片；不能誤傷其後開始的新 session。
- 座標新增後不可編輯，需刪除再新增。名稱、備註等沿用既有可編輯項目。
- 總隊長控制主隊並保留跨小隊既有管理權；小隊長只能新增、修改、刪除自己小隊的暫時集合點，以及開始、完成、結束小隊行程。後端依當前身分及資料範圍驗證。
- 小隊 membership 數量歸零才瓦解，離線不算離隊。刪除小隊行程、集合點及抵達內容，使待同步操作失效。重建用新 ID，不進入主隊歷史；可保留不含行程內容的最小刪除稽核紀錄。
- 兩筆不同請求或 Leader 複製／新增可具有相同地點，均保留獨立 ID。移除依 provider 地點合併的規則；同一 operationId 網路重送仍只能生效一次。

## Destination、位置與抵達

- 分開 journeyState、presenceState、arrivalTag，不能共用成員 status 表達全部狀態。
- ACTIVE Destination 是 session 目的地；IDLE 是成員目前可見範圍中，今天或未來、已排程且未完成的排序第一張卡；無卡為 null。未排程池不算。
- IDLE Destination 僅供預覽；Tag、抵達按鈕及自動判定只在 ACTIVE 生效。開始同一張卡的新 session 仍重設全員為未抵達。
- 成員可手動自由切換自己的抵達狀態直到結束／完成。離開抵達範圍不自動取消；手動取消後，同次停留不能立即被自動抵達覆蓋，離開再進入才重新觸發。
- 保留個人抵達半徑，以及位置精度、新鮮度及分享權限檢查；不以單次低品質 GPS 判定。保存判定來源、距離及精度。
- 抵達 key 包含 userId、destinationId、sessionId。不同卡片／新 session 重設；改名稱不重設。座標不可修改，因此不提供原卡座標版本更新流程。
- 位置可為 null 或過期；區分 capturedAt（取得時間）、uploadedAt（後端接收時間）、availability。使用原有狀態／定位等級對應頻率，精準定位按鈕使用最高等級並沿用既有期限。頻率不存為成員同步屬性。

## 完成後的歷史

- 完成只關閉成員操作 UI，不鎖死延遲抵達資料。操作必須綁定原 session，不能污染現在的 session。
- 合法離線操作晚到仍寫入原歷史：允許 completedAt=10:00、arrivedAt=10:05、receivedAt=10:10。不得以 arrivedAt 晚於 completedAt 作為唯一拒絕理由；仍驗證操作者及原 session 成員資格。
- 本人客戶端只在 ACTIVE 產生操作；後端接受帶原 session 的延遲事件。手機時間是回報時間，不可當作安全權限證明。
- Leader 可校正已完成主隊集合點中成員的抵達／未抵達，未完成的不得代改。校正 arrivedAt=null；獨立保留 correctedAt、操作者、來源及選填備註，不冒充本人實際抵達時間。
- 原始事件與校正事件皆保留。本人同裝置依 sequence 保持切換順序；相反來源依事件時間決定，Leader 校正用後端 correctedAt，平手用後端序號。延遲重送不重複產生事件。裝置時間異常保留為異常資料，不將其當作修改團隊狀態的依據。

## 同步介面與處理

- 操作 envelope 包含 operationId、actorId、deviceId、sequence、scope、entityId、sessionId、baseVersion、dependencyIds、occurredAt、payload；後端記錄 receivedAt 及結果以支持冪等重送。
- 本機 transaction 同時寫 optimistic snapshot 與 outbox。遠端快照更新後重新投影仍有效的待送操作，避免畫面倒退或覆蓋其他人的修改。
- 後端提供相容版本操作 RPC：驗權限、驗目標與狀態、按操作重新套用最新資料，只更新本次涉及的欄位。版本不同不能直接永久堵塞 queue。
- 同一行程依序開始→修改→結束，不合併中間歷史；不同實體無相依操作可繼續。位置可合併成最新樣本，通知另走 queue。
- 同裝置依序執行；不同裝置以後端成功接受順序決定一般修改最終值。手機時間只表示事件時間，不用於一般資料覆蓋優先權。
- 斷網／暫時伺服器錯誤退避重試；版本衝突自動讀取最新資料並重新驗證；已達成操作視為成功。失權、目標刪除、小隊消失等終止操作，自動重新計算畫面並提供非阻斷結果通知。
- 相依失敗時自動終止已失去前提的後續操作，其餘獨立操作繼續。既有 conflict 也須遷移進此機制；不直接清空使用者 queue。
- 對開始／結束等 transition 保留目標 session 檢查，不能因自動 rebase 結束後來的新行程。
- 通知後端驗證 Leader／成員類型，預設送給自己以外的適用成員並遵守接收偏好。離線通知預設五分鐘 TTL，過期不補送；只保證記錄並嘗試 APNs 投遞，不保證裝置顯示。不阻塞核心操作。

## 實作順序與驗收

1. 新增相容 migration／RPC 與事件、nullable arrivedAt、權限及冪等測試；保留舊客戶端必要介面，不重寫已部署 migration。
2. 改 outbox 排程、自動重新套用、既有 conflict 恢復及 snapshot 投影，再接入行程與歷史 UI。
3. 接入主／小隊權限、空小隊清理、複製地點與通知期限，最後移除同步手動抉擇 UI。
4. 驗證離線開始→修改→結束、兩裝置競爭、失權、帳號切換、舊 conflict、獨立 queue 不阻塞、重送只執行一次。
5. 驗證結束不完成、完成不等待全員、重新開始重設、ACTIVE 刪除先結束、不可修改座標、重複地點可保留。
6. 驗證手動 undo、自動抵達不立即反轉 undo、完成後延遲抵達、Leader 歷史校正 arrivedAt=null、事件衝突及不影響新 session。
7. 驗證 IDLE 無 Tag、定位不可用、小隊最後成員退出清理、失效 queue、通知過期與角色檢查。
8. 後端相容部署先於客戶端 OTA；審查後發布並觀察 queue 等待時間、重試／终止原因及自動解決比例。歷史資料缺少時間時保留 null，不捏造時間。
